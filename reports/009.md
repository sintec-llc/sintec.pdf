# 009: Print "match paper to PDF page size" is an option, off by default

## Which code paths pick the paper
- `PrintDraft::default()` (print_ui.rs): A4. Unchanged.
- `open_print()`: did NOT pick the paper (it keeps the previous draft with `..keep`).
- "Match page at 100%" button: the only place that set `paper`; it is an explicit click. No page-change handler, wasm or CLI path (`automation/printing.rs` uses the `paper` argument or `PAPERS[0]`) picks paper.
- "Auto portrait/landscape" (`Orientation::Auto`) only rotates the sheet; left alone.
- So today nothing picked paper automatically; the new option adds that automatic pick.

## Changes
- New preference `PdfCraftApp::match_paper_to_page` (default false), saved/loaded in the prefs JSON like `units`; checkbox in Preferences (Documents and view) next to Units; Russian string added to ru.tsv and rehashed.
- `PrintDraft::match_page(source)` holds the match (paper, Size, Actual, Auto orientation, sheet 0); the button calls it.
- `open_print()` calls it for the current page only when the preference is on. Off: paper/orientation untouched.
- Print engine API unchanged.

- Gates run: see commit (fmt, clippy, tests for engine, ui-egui).

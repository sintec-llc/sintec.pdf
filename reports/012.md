# 012: Print dialog must not pick paper from the PDF size

## What auto-picked before
- **Real cause**: `PrintDraft::default()` had `orientation: Orientation::Auto` (print_ui.rs ~136) and `auto_rotate: true` (~130). With Auto, `print::layout()` (crates/print/src/lib.rs, `oriented()` ~295, Multiple ~356) makes the sheet landscape for a landscape PDF. The Windows spool (spool.rs ~165-209, `paperFor`) then picks the driver paper that matches the sheet size and orientation, so the driver switched paper/orientation to follow the PDF. `open_print` kept the old draft with `..keep`, so the choice also stuck across documents.
- Not the cause: `match_paper_to_page` (default false at lib.rs ~921; prefs read after defaults at ~2022, only overrides when the key is present; a persisted `true` is only possible if the user ticked it). `d.match_page` at the "Match page at 100%" button is a click handler, not unconditional. `SizeMode::Fit` only scales, it doesn't choose paper. Paper default was already A4.
- Automation `auto_rotate: true` (crates/automation/src/printing.rs:73) is a separate headless path; unchanged. The Print crate's `Settings::default` (Orientation::Auto) is unchanged; it is not used by the dialog.
- dist/ 0.2.6 build is not present in this worktree, so what it contained could not be verified here.

## Changed
- Draft defaults: `orientation: Portrait`, `auto_rotate: false`. Auto stays selectable.
- Print dialog: checkbox "Match paper to PDF page size when printing" under the Paper selector, bound to `match_paper_to_page` (same string as Preferences, already in ru.tsv). Ticking it matches the current page at once. Off by default.
- Tests in crates/ui-egui/tests/print.rs: defaults (draft and after open_print), checkbox toggling in the dialog.

Failures seen (CI run 39598257647; logs via `gh api --allow-escape-sequences repos/sintec-llc/sintec.pdf/actions/jobs/<id>/logs`, jobs 119215888043 = macOS aarch64, 119215887946 = Windows):
macOS aarch64 (crates/ui-egui/tests): content.rs (typing_moving_styling_and_deleting_added_content, clicking_elsewhere_keeps_the_text_and_starts_a_new_box), control.rs:1280 control_quit_retains_blocked_content_typing_after_cancel, editing.rs (cropped_images_do_not_intercept_text_and_stay_inside_each_page, cropped_image_corner_resize_keeps_opposite_corner_and_scales_crop, editing_a_double_drawn_line_replaces_every_copy, one_editor_contains_mixed_styles_and_visual_rows, switching_from_a_narrow_editor_keeps_one_frame_and_a_wide_heading_on_one_line), forms.rs:153 typing_and_saving_in_the_same_frame_saves_the_last_keystrokes (Os NotFound), object_selection.rs (a_changed_text_editor_is_kept_when_group_selection_is_requested, modifier_clicks_extend_an_ordinary_selection_and_toggle_objects), ocr.rs:159 an_ocr_word_opens_for_editing_and_stays_open, ui.rs:367 the_integrated_title_bar_is_the_traffic_light_band.
Windows: tests/ui_group/updates.rs:233 skip_this_version_is_remembered ('Skip this version' label not found; it passed on an earlier CI run, so probably timing/flaky: look for a missing settle/wait).

Root cause found for most macOS ones: a click on text opens the font-substitution flow instead of the editor when the machine has no matching installed fonts. Reproduced on Windows: in crates/ui-egui/tests/content.rs add `app.fonts.installed_override = Some(Vec::new());` after PdfCraftApp::new() in harness(): the same two content tests fail. Tests that edit existing text must set `app.fonts.installed_override = Some(standard_faces())` (the helper exists in tests/editing.rs, text_box_*.rs; see its doc comment). Move the helper into one shared module (e.g. crates/ui-egui/tests/support/ included with #[path] or `mod`) and use it in EVERY harness/app constructor of the failing test files, and any other test file that clicks existing text. Do not change app behaviour.

Other items: forms.rs:153 reads a file path that does not exist on macOS (check the test: a hard-coded Windows/tmp path or a file created elsewhere: use std::env::temp_dir()/tempfile-style per-test dir); ui.rs:367 the title-bar test: find what it expects on macOS vs the fixture (it was green on main 0.2.5, so a change since then in chrome.rs/ui code or in the test setup broke it: bisect with git log -- crates/ui-egui/src/chrome.rs crates/ui-egui/tests/ui.rs); make it correct on macOS (cfg(target_os) gating only if the behaviour is intentionally Windows-only, and say so).
You cannot run macOS: to find similar breakage, simulate the machine-independence on Windows: temporarily run the whole ui-egui test suite with installed_override = Some(Vec::new()) forced for every PdfCraftApp::new() (e.g. via an env var read in a test-only constructor, not committed) to find further tests that depend on installed fonts, and fix those in the tests.

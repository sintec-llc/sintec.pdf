User report (after 014, build 0.2.7): the text box frames in Edit PDF do not reflect the real boundaries where the text wraps.

Context: 014 (merged, commit eb885d24 area) added DocView.kept_width / edit_text_ui::keep_width / canvas.rs: after a width-handle drag the box shows max(dragged width, text extent) even when the text itself does not use that width (widening a single line changes nothing in the PDF; engine keeps hard row breaks, crates/edit/src/text_regions.rs:244-247). Also block.rect is just the text's ink extent, not the wrap width the engine will use when the paragraph is rewritten (crates/edit/src/text.rs rewrite_block: width = style.width or block extent, clamped to >= one em; single line grows to page margin).

Required invariant: the frame's left/right edges must equal the width at which the text really wraps/will wrap when edited (the width the engine uses for rewrap), for every box: single-line, multi-line paragraph, table cell, single-word cell, rotated pages. Frame must not show a wider or narrower area than the text actually reflows to. Make the frame and the engine agree, e.g. by exposing the effective wrap width from the engine (TextBlock field or helper next to text_blocks) and drawing the frame from it, and by making a width drag set a width the engine really uses on the next rewrap/edit (so what you drag is what you get). If a kept UI-only width cannot be made real, remove or clamp it so the frame never lies. Keep 014's goals where compatible: no snap-back after a drag (drag result visible and stable), narrowing rewraps, clamp to the longest word, no merging of separate table rows/cells.
Check with a synthetic PDF shaped like a table (do NOT copy C:\Users\kochurin.a\Downloads\МаляковАА.pdf into the repo): multi-word cells, single-word cells, a 2-row block (heading + value), a soft-wrapped paragraph of 4+ lines. Tests: frame edges vs actual wrapped line extents after edit for each; widening then typing text wraps at the frame's right edge; narrowing then typing wraps at the frame; existing handle tests (011/013/014) still pass or are updated with reasons. CLAUDE.md constraints apply. cargo fmt, clippy --workspace -D warnings, cargo test --workspace green. Report the design and any limitation (e.g. PDFs do not store wrap widths).

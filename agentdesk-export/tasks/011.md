User feedback on 003 (edit_text_ui.rs: move_handle, handle_at, width_handles, page_input, plus object_ui.rs on_move_grip): the drag handle 'does not always work and does not always widen the box'. Find why by reading the code and reproducing with the egui test harness (crates/ui-egui/tests), then fix. Suspects: handles/grip drawn and hit-tested only while the pointer hovers the box (moving from the box to the grip, which sits ABOVE the box, drops the hover so nothing is grabbable; likewise the width handles at the left/right edges 7px wide); grip hidden when `active` (a box is being edited) or when the page is rotated (`upright` false); the press being taken by object_ui selection/marquee or another widget first; drag_started needing movement threshold; hover limited to xf.rect so the grip above the page top / off page is lost; the width drag not being applied (min width, text reflow not re-layout) or ending on pointer leaving. Make: grip and both width handles visible and grabbable for the hovered OR selected/being-edited box, hit areas generous (>= 24px), a grab continues until release wherever the pointer goes, widening by the side handles always changes the box width (also while editing), rotated pages work too.
Done when: tests for hover->grip transition, dragging the grip moves, dragging each side handle widens/narrows, while editing, and on a rotated page. fmt, clippy, tests green.

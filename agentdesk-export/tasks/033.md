Still wrong after task 027 (build 0.3.0): when the original font is replaced by a substitute (not embedded / not installed), the text shown in the in-place edit field (preview while typing) looks different from (a) the final rendering after the edit is committed and (b) the original font. Expected: the preview uses exactly the same font face, weight, style, size, letter/word widths and line wrapping as the committed result, and the substitute is the closest metric-compatible match to the original (glyph widths, see tasks 004/006/027).
Where: crates/ui-egui (edit_text_ui, canvas, text_panel, fonts/text_fonts), the engine side that renders the committed text. Find the divergence: probably the egui editor uses a different font family/fallback chain than the engine's final render. Make both go through one font-resolution function. Add tests that the resolved face for a given (original font name, flags) is identical for preview and commit, and a metric test on widths. Use the PDFs available in the repo test fixtures; if a table-like PDF with Cyrillic text is available, use it. Never use fonts from Adobe or installed system fonts for embedding (AGENTS.md). Done when fmt, clippy -D warnings and cargo test (touched crates) are green; describe a manual check.

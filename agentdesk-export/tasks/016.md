Goal: bring upstream PdfCraft v0.8.0 (git remote 'upstream', tag fetched already) into our branch. Our branch already contains upstream up to v0.7.1 (merge-base 7163ba3d). v0.7.1..v0.8.0 is ~73 commits. Do a real `git merge v0.8.0` (keep history), resolve every conflict, workspace builds, all checks green.

Rules (our fork = Sintec.PDF, see README/AGENTS/CLAUDE.md, ATTRIBUTION, zz_SIGNING.md):
- Keep our branding, version (0.2.7 in Cargo.toml and Cargo.lock; do NOT take upstream's version numbers), our release/update URLs, our CI/packaging decisions (upstream's Linux/FreeBSD/web/ARM jobs were removed here; keep them removed). Keep ATTRIBUTION required notices.
- UI languages: we ship ONLY English and Russian. Language .tsv files for other languages were deleted by us; do not restore them (resolve 'deleted by us' conflicts by keeping them deleted), but take upstream's new/changed English source strings into en handling and add Russian translations for new strings in crates/ui-egui/src/i18n/ru.tsv (leading TAB, empty context column; check line endings first, byte-level edits; then `python zz_rehash.py crates/ui-egui/src/i18n/ru.tsv`).
- Our own features must survive and keep working; where upstream touched the same code, merge both intentions, prefer upstream's structure and re-apply our behaviour on top: floating text panel (text_panel.rs, panels.rs), text box move grip/width handles and kept width/frame logic (edit_text_ui.rs, canvas.rs; tasks 003/011/013/014/015), tab tear-off and cross-process tab drag (tear_off.rs, doc_windows.rs, docking.rs; 005/010), bundled substitute fonts (004), glyph-width font identification (006), scanner (scan_ui.rs, tests/scan.rs with mock data; page.scan stays in PICKERS in the tests), Excel/Word/PPT/HTML/RTF table export, print paper auto-fit option off by default (009/012), stability fixes (008), signing, setup.exe launcher.
- Never discard either side silently; when you drop code, say why in the report.
Done when: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` are green, `cargo xtask layers` (if it exists as a gate in xtask/src/gates.rs) passes, the merge is committed on the task branch, and the report lists: conflicts per file and how each was resolved, features of ours that needed re-application, anything left failing/ignored with the reason. Check the app actually starts (cargo run -p pdfcraft briefly, or the project's own smoke test).

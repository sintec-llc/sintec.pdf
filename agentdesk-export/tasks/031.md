title = "Tab moved to another window: the source window must close, not stay on the start page"
tier = "hard"
+++

Regression (seen again in build 0.3.0, after tasks 010/029): when a tab is dragged into another window's tab strip, it joins the target, but the source window does NOT close; it stays open showing the empty start (title) page. Expected: if the moved tab was the last one in the source window, that window (or process, for tear-off windows) closes by itself; if other tabs remain, it simply keeps them.
Where: crates/ui-egui/src/tear_off.rs, doc_windows.rs (cross-process hand-off and the same-process path), possibly the ghost overlay from 029 keeping a viewport/drag state alive.
Do: reproduce with a test (same-process and cross-process hand-off paths), find why the close is skipped, fix, add regression tests that assert the source window closes after its last tab left and survives with remaining tabs. Cover the abort cases (drop refused, target gone: tab must come back, window must NOT close then). Never-panic rules. Done when fmt, clippy -D warnings and cargo test -p pdfcraft-ui-egui are green; describe a manual check in the report.

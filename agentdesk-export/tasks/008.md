title = "Stability audit: find and fix crashes, panics, hangs and leaks"
tier = "hard"
+++

Goal: a thorough back-check of the app for instability. The user reports it is unstable.

Method: (1) grep the shipped (non-test) code of crates/ui-egui, engine, fonts and the app crates for unwrap()/expect()/indexing/slicing that can panic on real input (empty docs, 0 pages, page index after page delete/reorder, closed tab, stale DocId, zero-size rects, NaN/inf geometry, malformed/encrypted/huge PDFs), arithmetic overflow, and unbounded loops. (2) Check that every long job and background thread (OCR, scan, font discovery, export, render) handles cancellation, closed documents and app exit without leaving a dead state, deadlock (Mutex held across UI calls) or leaking threads/temp files (e.g. sintec-scan-<pid> dirs). (3) Check the state transitions around undo/redo, closing a tab while a job runs, tab tear-off to another process, reopening, save-as over an open file. (4) Check memory: unbounded caches (textures, rendered pages, font caches) and whole-file clones. (5) Run the existing fuzz/corpus tests if any and try a handful of hostile PDFs generated in tests.

Fix what you find with the smallest safe change, each with a regression test. Do NOT change features. Keep a list in the final report: found, fixed, left (with reason).
Gates: cargo fmt --check, cargo clippy -p xtask -p pdfcraft-engine -p pdfcraft-fonts -p pdfcraft-ui-egui --all-targets -- -D warnings, cargo test same crates. Tests must never open the real scanner or native dialogs.

User feedback on 009: in the 0.2.6 test build the print menu still picks the paper automatically (to match the PDF page), by default, and there is no visible way to switch that off. They asked for this behaviour to be OFF by default. 009 only added a Preferences checkbox (`match_paper_to_page`, lib.rs, print_ui.rs open_print) and concluded nothing auto-picked before - that does not match what the user sees, so find the real cause. Check every path: open_print and PrintDraft (print_ui.rs; `..keep` keeps old draft), `Orientation::Auto` ('Auto portrait/landscape', default) and `SizeMode::Fit` default which rotate/scale to the page, 'auto_rotate', the preview, the Windows printer driver/DEVMODE paper selection in the spool crate (does it pick a paper by page size?), the saved prefs file (a stale persisted value true?), and whether the checkbox in Preferences actually persists and is read. Also verify what the dist 0.2.6 build contained.
Deliverables: (1) by default nothing picks the paper from the PDF size: paper = A4 (or the printer's default), orientation not auto-rotated unless the user chooses it; (2) put a clearly labelled checkbox in the Print dialog itself next to the Paper selector ('Match paper to PDF page size', bound to the same preference, off by default) so it can be turned off/on there; keep the Preferences one; Russian strings in ru.tsv; (3) tests for default-off and for the checkbox. Report in reports/<id>.md what auto-picked before. fmt, clippy, tests green.

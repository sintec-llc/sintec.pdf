Goal: the print dialog currently picks the paper to match the PDF page size automatically. Make this behaviour a user-selectable option and turn it OFF by default. With the option off, the paper the user picks (default A4, as now) is used for every print, and the PDF page size does not change it.

What's wrong today: the paper is changed by the page-size match. In crates/ui-egui/src/print_ui.rs the "PDF page: ..." row shows a "Match page at 100%" button (around lines 835-850). Clicking it sets paper = matching_paper(page size), handling = Size, size = Actual and orientation = Auto. Check whether anything else changes the paper without a click (for example on dialog open in open_print(), around lines 277-312, or on a page change). Also check the "Auto portrait/landscape" orientation (print_ui.rs ~971), which rotates the sheet to the page. Report in reports/009.md exactly which code paths pick the paper automatically. If the automatic pick is not the button, say so and fix the path you found.

Where: crates/ui-egui/src/print_ui.rs (PrintDraft, open_print, the Size controls); crates/print/src/lib.rs (matching_paper, layout) only if needed; the Preferences storage used by other settings (look for an existing bool preference in ui-egui and follow its pattern, e.g. how `units` is stored).

What to build:
1. A boolean preference, default false, for example "Match paper to PDF page size". Put it in Preferences next to the other print/units preferences if such a place exists. Store it the same way as the existing preferences.
2. When it is off: nothing changes the paper or the orientation automatically. The "Match page at 100%" button stays available as an explicit action, so the user can still use it by hand (keep it unless it is clearly the automatic path). The default paper stays A4.
3. When it is on: the current automatic behaviour, unchanged.
4. Keep the PrintDraft default (A4) and the engine API (print::layout, matching_paper) unchanged. Feature changes beyond this option are out of scope.

How to tell it's done:
- Default preference is off; with a fresh profile, opening the print dialog on a page of a non-A4 size keeps the paper the user selected (test: draft.paper unchanged after open_print()).
- With the option on, the automatic match works as before (test).
- The preference survives restart the same way other preferences do (test or check the existing preference test pattern).
- Add/adjust regression tests in crates/ui-egui/tests/print.rs (the existing "Match page at 100%" test there must still pass or be updated to enable the option first).
- Gates: cargo fmt --check; cargo clippy -p pdfcraft-engine -p pdfcraft-ui-egui --all-targets -- -D warnings; cargo test -p pdfcraft-engine -p pdfcraft-ui-egui -p pdfcraft-print (or the print crate's actual package name). Tests must never open a real printer or native dialog.
- Branch from feature/0.2.6. Another task (008) also touches pdfcraft-ui-egui; keep the diff small so it merges cleanly.
- Write reports/009.md: what picked the paper automatically, what was changed, tests run.

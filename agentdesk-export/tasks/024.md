Runs AFTER the PdfCraft v0.9.0 sync (tasks 021-023, 018, 019), on the new base. Goal: make PDF size reduction really effective and let the user choose.
1. Study what exists: crates/optimize (+ crates/engine/src/optimizer.rs, "optimize.reduce" -> reduce_file_size in ui-egui, Dialog::Optimize "optimize.advanced", automation tools). Measure on synthetic and real-like PDFs (scanned pages, photo-heavy, text-heavy, many duplicate fonts/images, uncompressed streams): what is already done (flate recompress, object streams, dedupe, unused-object removal, image downsample/JPEG recompress, font subsetting, metadata strip) and where the bytes go.
2. Implement the missing effective techniques, each with tests: recompress images (downsample to a target DPI by quality level; re-encode JPEG at a quality level; convert lossless flate photos to JPEG; 1-bit scans keep CCITT/JBIG2-like or flate with predictor), better flate (max level / zopfli-style only if a pure-Rust dep is acceptable under deny.toml and AGENTS.md - otherwise use the best level of the existing crate), object streams + xref streams, dedupe identical streams and images, subset/drop unused fonts, remove unused resources, thumbnails, metadata, embedded files only when the level allows. Never change page appearance beyond the level's documented image downsampling; never lose text, forms, signatures-need-warning, bookmarks or links at Light/Medium.
3. Three presets: Light (lossless only: structure/stream recompression, dedupe, cleanup), Medium (images to ~150 dpi, JPEG ~75), Strong (images to ~100 dpi, JPEG ~55, strip extras). Put the preset table in one place and in docs.
4. UI: the "Reduce file size" command opens a small dialog (English + Russian strings; add to ru.tsv with a leading TAB and empty context, check line endings, byte-level edits, then `python zz_rehash.py crates/ui-egui/src/i18n/ru.tsv`) with a radio choice Strong / Medium / Light. Next to each choice show the ESTIMATED resulting file size (and % saved) BEFORE the user picks. Estimation must be cheap and honest: compute it from the document (sum of image bytes at the new dpi/quality estimated by a sampled trial-encode of a few images or a size model, plus the non-image bytes after lossless recompression) on a worker thread without freezing the UI, show 'calculating...' meanwhile, and label values as approximate (~). Cancel leaves the file untouched; the real result after applying is shown in a toast (before/after).
5. Keep the Advanced optimize dialog working; automation/CLI tool gets a `level` parameter (light|medium|strong) with the same presets.
Constraints: Sintec branding, en+ru only, never-panic rules for new non-test code (AGENTS.md §4), no unwrap on input-derived values, large files must not block the UI. Done when fmt, clippy --workspace --all-targets -D warnings, cargo test --workspace are green, with tests for each preset's size ordering (strong < medium < light < original on a fixture with images) and for the estimator being within a stated tolerance of the real result. Report: techniques added, measured savings per fixture and level, estimator accuracy, limitations.

**What changed**
- **Scanning on Linux:** it uses SANE (`scanimage`). The previous run had added this but left the build broken on every platform, because the "SANE not installed" error had no message; it now has one in English and Russian. The audit also found that scans went through a predictable folder in the shared `/tmp`, where another local user could tamper with or read them. The page is now read straight from `scanimage`'s output and nothing is written to disk.
- **Update check:** on Linux it no longer finds the Windows MSI as its installer; it opens the release page instead.
- **Packaging (`packaging/linux`):** rebranded to Sintec.PDF (finished from the previous run). The programs install as `sintec-pdf` and `sintec-pdf-cli`, with the app id `io.github.sintec_llc.sintec_pdf` and a desktop entry in English and Russian for `application/pdf`. That id applies on Linux only; Windows and macOS keep theirs. Models and fonts go to `share/sintec-pdf`, so nothing clashes with an upstream PdfCraft installed alongside.
- **`ci.yml`:** new `linux` job on ubuntu-22.04 (fmt, clippy `-D warnings`, the whole test suite under a virtual X display, layers, assets), which uploads the AppImage, .deb and CLI tarball as artifacts.
- **`release.yml`:** new `linux` job that builds `sintec-pdf-<v>-linux-x86_64.AppImage` (plus its `.zsync`), `.deb` and `sintec-pdf-cli-<v>-linux-x86_64.tar.gz`. It checks their contents and that `--version` runs, and the draft-release job now waits for it, so these files land in the draft release and `SHA256SUMS.txt`. aarch64 is a commented-out matrix row: GitHub's Arm runners may not be available or free on a private repo.
- **Docs:** `docs/releasing.md`, the README (platform list, Linux install and build), `CHANGELOG.md` and a `ROADMAP.md` progress line.

**Audit**

All MSI and registry code is already Windows-only.
- **Needs a Linux implementation:** the remaining-work list below.

**Not verified without a Linux runner:** none of the tests have run on Linux; I could only cross-check compilation, using zig as the Linux C compiler. Also unverified: the apt package list, nfpm 2.47.0, AppImage building, and the new `linux_scans_through_scanimage` test (it creates and runs shell scripts, which can rarely fail with "text file busy"). The new CI job will show all of this.

**Remaining for a first Linux release:**
- **Wayland tab drops:** dropping a tab on another window compares window-local coordinates, so a tab can be sent to the wrong window. The fix is to skip cross-window matching when the window position is unknown.
- **Drag ghost outside the window:** Windows only for now; possible on X11.
- **Single instance:** the socket under `$XDG_RUNTIME_DIR/pdfcraft`, plus the recovery and clipboard-cache folders, still use upstream names. A Sintec launch can hand its files to a running upstream PdfCraft.
- **Paper sizes:** CUPS only gets a paper name for A3–A5, Letter, Legal, Tabloid and labels; A6, A0–A2 and the ARCH/ANSI sizes print on the queue's default paper.
- **Office → PDF:** needs a LibreOffice path on Linux.
- **macOS scanning:** the "scanning works on Windows" message is still worded for Windows only, and is now inaccurate since Linux scans too. I left it so macOS behaviour doesn't change.
- **rpm and aarch64 builds.**

Two new files must be committed with this change or the build breaks: `packaging/linux/io.github.sintec_llc.sintec_pdf.desktop` and `.metainfo.xml.in`. The zig/actionlint tools are in `C:\Users\kochurin.a\sintec-pdf\tools-028-zig`, outside the worktree.

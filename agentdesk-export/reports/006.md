# 006: Identify anonymised fonts by their glyph widths

Branch `auto/006` at db3c373f; tiers standard.

## Brief

Goal: identify anonymised PDF fonts (e.g. `CIDFont+F1`, no usable name table) by a glyph-width fingerprint, and use it in ranking and the analysis text.

Files:
- crates/engine/src/text_fonts.rs: `FontFile` (l.9-15, derives PartialEq; add a width field); `discover` (l.61-101) reads each face's bytes, so compute widths here for a fixed probe set (A–Z, a–z, Cyrillic А–я/Ё/ё, 0–9, common punctuation), normalised to 1000 em. `Wanted` (l.133-143) needs the PDF side's widths and a `from_facts` path (l.149). `Match` (l.205) and `rank` (l.228-256): add a fingerprint match between Exact (10_000) and Alias (6_000). Tests live in the module at l.258+; `face()` helper at l.263.
- crates/edit/src/text.rs: `FontFacts` (l.123-145), `font_facts` (l.169-207). Widths come from `pdfcraft_fonts::pdf::Metrics` (crates/fonts/src/pdf.rs l.31; `width(code)` l.720; `text_of(code)` l.755 for ToUnicode, `codes` l.693). Map each char to its code and width; only chars the font actually has.
- Installed-face widths: check which font parser crate pdfcraft_fonts already uses (hmtx/cmap for TrueType/OTF, CFF charstring widths otherwise). Reuse it; don't add a dependency without need.
- crates/ui-egui/src/font_substitute.rs ~l.486: the analysis/display line that shows the match reason. Show the fingerprint there.

Rules:
- Score = mean absolute difference over shared characters (scaled to 1000 em). Need at least 8 shared characters; otherwise no claim (no match).
- Close means mean difference < 15 units.
- CLAUDE.md: no unwrap/expect/panic, no indexing with input-derived positions, checked arithmetic, guard against NaN/inf and divide-by-zero (units_per_em = 0), cap loops over font data.
- Any new UI string needs a line in crates/ui-egui/src/i18n/ru.tsv (leading TAB, empty context column), then run `python zz_rehash.py crates/ui-egui/src/i18n/ru.tsv`. Working-tree files are CRLF: edit with `newline=''`.
- Gates: `cargo fmt --all --check`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace`. Commit message: task id, e.g. "006: ...".

Done when: synthetic tests show (a) a PDF font whose widths match an installed face (with no name) ranks it as Exact-level, (b) fewer than 8 shared characters gives no claim, (c) mean difference ≥ 15 gives no claim, and (d) the analysis text shows the fingerprint. Gates are green.

## Worker summary

Anonymised PDF fonts (e.g. `CIDFont+F1`) are now matched to installed faces by a glyph-width fingerprint. `cargo fmt --all --check` and clippy (`--all-targets -D warnings`) are clean, and no tests failed in the workspace run. I didn't test it against a real anonymised PDF or a real installed face; the new tests use synthetic widths.

- **Probe set and installed faces:** `crates/fonts/src/embedding.rs` gets `probe_chars()` (A–Z, a–z, А–я, Ё/ё, 0–9, common punctuation) and `probe_widths(bytes)`. It reads advances through the `skrifa` crate already in use and normalises them to 1000 em. It guards against `units_per_em = 0` and non-finite values. `discover` stores the result in a new `FontFile.widths` field.
- **PDF side:** `FontFacts.widths` in `crates/edit/src/text.rs` is filled by mapping each code to its ToUnicode character and `Metrics::width`. It keeps single probe characters only, first code wins, and the loop is capped at 0xFFFF codes.
- **Scoring:** `rank` uses a new `Match::Fingerprint` between Exact and Alias, worth 8,000 points. The score is the mean absolute difference over shared characters. It needs at least 8 shared characters and a mean below 15 units; otherwise it makes no claim. A real name match still wins as Exact.
- **UI:** the substitution dialog treats Fingerprint like Exact. The analysis line reads "Face — same glyph widths (off by 3.0 on average)", with a Russian translation added to `ru.tsv` and rehashed.
- **Tests:**
  - A synthetic unnamed font ranks the matching face first.
  - Fewer than 8 shared characters gives no claim.
  - A mean difference of 15 or more gives no claim.
  - The analysis text shows the fingerprint.

`FontFile` and `Wanted` each have a new field, so the struct literals in `panels.rs`, `font_substitute.rs` and two UI test files needed it too.

NOTES:
- `Match` gained `Fingerprint` (Other < Alias < Fingerprint < Exact); any new `match` on it must handle that variant.
- `FontFile` and `Wanted` struct literals now need `widths` (`FontFile` has no `Default`).
- `ru.tsv` in this tree is LF, not CRLF as the brief said; check for `\r` before assuming a line ending.

## Worker summary

A width drag on a paragraph box now stays visible after release. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` are all green.

**Design decision.** The fix is UI-side. On release, a handle drag saves its new width in the view as a `KeptWidth` (`edit_text_ui.rs`), keyed by page and block. `keep_width` applies it when the page's blocks are re-read after the drag's own edit (`canvas.rs`). The box then shows the larger of the dragged width and the text's real extent:
- **Widening:** a single-line box stays wide even though no text changes.
- **Narrowing:** a multi-word cell rewraps and stays at the dragged width.
- **Clamping:** a width below the longest word shows that word's width instead. A single-word cell therefore keeps its own width and its text is unchanged.
- **Dropped:** the kept width is cleared as soon as the document changes again. That covers a text edit, a move, undo, or any other edit.
- **Later drags:** they start from the width the box shows, so widening then narrowing is consistent.

The engine is unchanged (`text_regions.rs`, `text.rs`). Hard row breaks are kept, so separate table rows and cells never merge into one paragraph. Default text editing is unchanged.

I added `DocView::shown_text_boxes(page)` as a public accessor so tests can read the boxes as shown. I did not touch `on_move_grip` or `handle_at`.

**Tests.** `crates/ui-egui/tests/editing.rs` has a synthetic table fixture (Courier, ToUnicode map, rows far apart) with the Russian cells 'Доступ к сети Московского офиса', 'имя входа (login)' and the single word 'Сеть'. It covers:
- widening a single-line cell
- widening then narrowing
- narrowing a multi-word cell (rewraps and stays narrow)
- a single-word cell clamping
- 'Московского' limiting a narrowed cell

I changed one existing test, `a_quick_flick_on_either_edge_rewraps_the_paragraph`. It widened a box and then narrowed it from the raw text width, which relied on the old snap-back. It now narrows from the shown width.

One known gap: if a width drag's edit is refused, the kept width is applied at the next document change instead. I accepted that and did not guard against it.

NOTES:
- Block `rect` is always the text extent. The user-dragged box width lives only in `DocView.kept_width` and is applied to the cached `edit_lines` by `edit_text_ui::keep_width`; it is dropped on the next document-generation change.
- `DocView::shown_text_boxes(page)` returns the boxes as shown (kept width included); tests should use it, because `doc.text_blocks` has the raw extent.

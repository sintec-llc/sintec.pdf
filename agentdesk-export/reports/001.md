## Worker summary

`feature/0.2.6` is now clean for `cargo fmt --all --check`, `cargo clippy --workspace -- -D warnings` and `cargo xtask assets`. `cargo test -p pdfcraft-edit -p pdfcraft-engine -p pdfcraft-ui-egui` passes with no failures. I did not run the whole-workspace test suite or confirm that the new tests fail when the feature is reverted. Nothing is committed.

**Call site.** `suggest_fonts` is called in the app's per-frame `update` in `crates/ui-egui/src/lib.rs`, right after `process_pending_edits()`. It runs when the Edit text tool is active, no modal dialog is open, the document allows modification, and a page is shown. I used `views[i].current` as the page.
- **Why here:** `canvas.rs` and `page_input` are free functions without `&mut PdfCraftApp`, so they can't call it. `page_fonts` is cached per edit generation, so repeating the call each frame is cheap.
- **No reopen after dismissal:** `suggest_fonts` skips fonts already in `fonts.suggested`, which is filled when the dialog first opens. A test confirms it stays closed after Cancel. I left the `Match::Other` logic alone.

**Test hook (new public field).** I added `FontSubstitutes::installed_override`, which makes the installed-font list deterministic. `PdfCraftApp::installed_faces()` uses it instead of scanning the system fonts. The new UI tests need it, and without it they depend on the machine's own fonts.

**Tests added**
- **pdfcraft-edit:**
  - `font_facts` reads family "Rect Font" and weight 700 from the embedded program, while `/BaseFont` is `CIDFont+F1`. `first_unencodable` returns the first character the font can't encode. The synthetic font is a Type0/CIDFontType2 with a ToUnicode map.
  - The edit crate pulls in the engine's fixture with `#[path]`. `font_fixture.rs` gained `cff_font_with_weight(weight)`, which adds an OS/2 table.
- **pdfcraft-engine:** `Wanted::from_facts` takes the program's family, weight, italic and serif over the PDF's flags, while an explicit bold/italic request still wins.
- **pdfcraft-ui-egui (`tests/font_substitute.rs`):**
  - A bold edit on a "RectFont" paragraph uses the installed bold face, not Helvetica-Bold.
  - The substitution dialog opens once when the Edit text tool is selected, and stays closed after Cancel.

**Existing tests made hermetic.** Once the suggestion dialog and the installed-face lookup were live, six `editing.rs` tests started failing, because their results depended on this machine's fonts and the dialog opened over the editor. I gave their harnesses a fixed set of installed faces: a `standard_faces()` helper (Arial, Times New Roman and Courier New, regular, with paths that don't exist), plus an "Inter" face for the one test that embeds Inter. The fake paths mean a styled edit falls back to the standard PDF fonts, as those tests expect.

**Russian string.** I added "No similar font is installed. Choose the font edited text in it is set in." to `ru.tsv` and re-ran `zz_rehash.py`, which updated `ATTRIBUTION.toml`.

`cargo fmt` also reformatted some existing lines in `text.rs` and `text_regions.rs`.

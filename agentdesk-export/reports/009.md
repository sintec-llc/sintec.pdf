## Worker summary

"Match paper to PDF page size when printing" is now a Preferences option, off by default. With it off, opening the print dialog leaves the paper and orientation alone. The paper stays A4 unless the user changes it. fmt, clippy and the engine and ui-egui tests all pass. I didn't run the `pdfcraft-print` package tests; I made no changes in that crate.

**What picked the paper before:** nothing did automatically. The "Match page at 100%" button was the only code that set the paper, and it only runs on a click. `open_print()` doesn't touch the paper, and there is no page-change handler or wasm/CLI path that picks one. "Auto portrait/landscape" only rotates the sheet, so I left it alone. The brief says "when on, behaviour exactly as today", but today there is no automatic match. So the option adds one: with it on, opening the dialog applies the same match as the button to the current page. If you meant something different by "as today", say so.

**Changes:**
- **Preference:** `PdfCraftApp::match_paper_to_page` defaults to false. It is saved and loaded in the prefs JSON the same way as `units`, and bad data leaves it unchanged. The checkbox sits next to Units in Preferences.
- **Matching:** the button's logic now lives in `PrintDraft::match_page()`. The button still works as an explicit action either way. `open_print()` calls `match_page()` only when the option is on.
- **Translation:** the Russian string is added in `ru.tsv` and rehashed, so `ATTRIBUTION.toml` has a new sha256.
- **Print crate:** `print::layout`, `matching_paper` and the A4 default are unchanged.
- **Tests:** two new tests in `crates/ui-egui/tests/print.rs`: one for open-print with the option off and on, one for the preference round-trip. The existing Match-page tests still pass unchanged.
- **Report:** `reports/009.md` lists the paper-picking paths, the changes and the tests.

NOTES:
- Nothing in print_ui.rs picked the paper automatically before 009; only the explicit "Match page at 100%" button did.
- `PrintDraft::match_page()` is the shared match logic; `PdfCraftApp::match_paper_to_page` gates it in `open_print()`.
- Editing `ru.tsv` changes the sha256 in `ATTRIBUTION.toml`, so rerun `zz_rehash.py` after each edit.

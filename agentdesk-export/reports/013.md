**Confirmed root causes (both reproduced with failing tests first):**
1. **Right handle under the Format text panel.** When a press lands on the panel, `update_text_panel_pointer` (canvas.rs) hides the pointer from the page. A box that reached under the panel (about 834–1134 px in a 1200 px window) therefore lost its right handle completely.
   - The panel now steps to the left side when it would cover the open box's grip or width edges.
   - If both sides are covered (a narrow window), a press on the grip or edge zones goes to the page, not the panel.
   - New field: `DocView.open_box_zones`, published each frame by `edit_text_ui::page_input` and handed to the panel as `panel_yield`.
2. **90/270 pages had no width handles.** Edge grabbing was gated on `rotation % 180 == 0`.
   - Handles, grab zones, the drag preview and the cursor now run along the screen's vertical on quarter-turned pages, through the new `width_is_vertical` helper (page `/Rotate` plus view rotation).
   - `Grip::Left` is the edge where the text starts.
   - `on_move_grip` uses the same logic, so object_ui no longer starts a marquee there.

**Checked, no bug:**
- **Drag maths:** width follows the pointer at zoom 0.5, 1.0 and 1.5, with the 12 px minimum (`MIN_BOX_WIDTH`) clamp kept.
- **Persistence:** the width survives undo, redo, save and reopen, and the text reflows.
- **Press order:** the new grab zones go through `on_move_grip`.
- **Auto-width single line:** a handle drag always sets an explicit width, so it becomes a fixed-width paragraph. I left this as it was and documented it in a code comment at the commit site.

**Caveat:** `TextBlock.rect` is the text extent, not the box width. Widening past the text merges lines and the rect only grows to the longest row. After a save and reopen the box reads back as its widest row, so a wider-than-text box is not stored.

New tests are in `crates/ui-egui/tests/text_box_width.rs`.

NOTES:
- `TextBlock.rect` is the text extent, not the box width. Handle-drag tests need wrapped multi-row text; a Courier fixture with 12 pt word steps works.
- `DocView::set_zoom` is the way tests change zoom; `text_panel_rect()` shows where the panel is.

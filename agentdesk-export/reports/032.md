# 032: Print dialog: orientation default must be Automatic, not Portrait

Branch `auto/032` at 5748442c; tiers standard.

## Brief

Bug in build 0.3.0: the print dialog opens with Portrait orientation selected; the default must be Automatic (auto portrait/landscape by page shape). Where: crates/ui-egui/src/print_ui.rs and the print settings/state/default + persisted Preferences (a saved old value 'portrait' from earlier versions must not pin it: if the stored value was never chosen explicitly by the user, treat as Automatic; check how settings are stored and migrate sensibly). Note the paper-size auto-fit switch stays OFF by default (tasks 009/012) - do not change that. Add tests: default orientation is Automatic; a landscape page prints landscape by default; explicit user choice still persists. Done when fmt, clippy -D warnings, cargo test -p pdfcraft-ui-egui (and the crate with print logic) are green.

## Worker summary

The print dialog now opens with Automatic orientation instead of Portrait. The fix is one line in `crates/ui-egui/src/print_ui.rs`: the `PrintDraft` default is `Orientation::Auto`.

The print dialog's draft is never saved to Preferences. Orientation is only held in memory and starts from the default each launch, so no old saved "portrait" value can pin it and no migration was needed. The paper-size auto-fit switch is untouched and stays off.

I only ran `cargo test -p pdfcraft-ui-egui --test print` (18 passed) and `cargo fmt -p pdfcraft-ui-egui`. I did not run clippy with `-D warnings`, the rest of the `pdfcraft-ui-egui` tests, or the `print` crate's own tests.

I rewrote `print_defaults_pick_no_paper_and_do_not_rotate` in `crates/ui-egui/tests/print.rs`, which previously asserted Portrait, to cover the three cases you asked for:
- **Default:** orientation is Auto.
- **Landscape page:** a landscape page on the default A4 paper prints on a landscape sheet.
- **Explicit choice:** an explicit Portrait choice gives a portrait sheet and survives reopening the dialog.

I did not revert the fix to watch the new assertions fail first.

NOTES: The print draft (`PrintDraft`) is not persisted. Orientation lives only in the in-memory dialog state.

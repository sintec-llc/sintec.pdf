## Worker summary

Both tests now pass, and the whole `cargo test -p pdfcraft-ui-egui` run is green. `cargo fmt --check` and `clippy --all-targets -D warnings` are clean.

**Cause:** this was a test problem, not an app bug. When the Preferences dialog opens, it needs more than 3 frames to settle into its final position. After 2–3 frames, "Right" sat at y≈341. After 12 frames it sits at y≈182, the same row as "Left". `Node.click()` uses the rect from the last frame, so the click landed where the button used to be. The app's own logic is fine: `set_tools_on_right(true)` returns `Ok` and flips the state when called directly.

**Fix:** in `crates/ui-egui/tests/ui.rs`, both tests now run 12 steps (up from 3 and 2) after opening Preferences and before clicking. I fixed the waiting, not the assertions. I didn't run a bisect, because the stale-rect cause was clear without it.

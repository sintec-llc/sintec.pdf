# 029: Tab drag ghost must follow the pointer outside the window (floating overlay window)

Branch `auto/029` at d9d574cd; tiers standard.

## Brief

Today (crates/ui-egui/src/drag_ghost.rs) the translucent ghost of a dragged tab/pages is an egui Area drawn inside each window only when the pointer falls inside that window (Ghost.screen in screen points, doc_windows.rs:140, :259). The moment the pointer leaves the window the ghost disappears, so the user has no visual cue when dragging a tab out to another window or to the desktop (tear-off).
Goal: while a tab (or pages) drag is under way, the ghost keeps following the pointer everywhere on the screen, also outside any Sintec window.
Approach (check feasibility first, report if another is better): a small borderless, always-on-top, transparent, non-focusable, mouse-passthrough egui viewport (ViewportBuilder: with_decorations(false), with_transparent(true), with_always_on_top(), with_taskbar(false), with_mouse_passthrough(true), with_active(false)) created on drag start / when the pointer leaves the source window, moved with ViewportCommand::OuterPosition to Ghost.screen + OFFSET each frame (pointer position outside the window needs a global source: winit gives cursor position only while captured; use the captured drag events, and on Windows GetCursorPos via the existing platform crate if needed, behind cfg), closed on drag end/cancel/escape. Inside windows keep the current in-window ghost (do not draw twice: when the overlay is shown, suppress the in-window Area). Must work on Windows first; macOS and Linux may fall back to the current behaviour via cfg, without breaking compile.
Constraints: no flicker or focus steal (the overlay must not take focus or drop the drag), must not interfere with the cross-process tab drop (task 010 / tear_off.rs), never-panic rules, large pointer jumps fine, no leak of the overlay if the app loses the drag (cleanup test). Add unit tests for the ghost position/lifecycle logic (pure functions), and describe a manual check. Done when fmt, clippy -D warnings, cargo test -p pdfcraft-ui-egui are green.

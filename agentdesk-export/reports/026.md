## Brief

User feedback on 024 (Reduce file size): Light and Medium give the same result, Strong damages image quality a lot. Goal: the MAXIMUM size reduction with MINIMUM visible loss. Research and implement better algorithms.

Where: crates/optimize (images.rs, lib.rs), crates/engine/src/optimizer.rs (Level::settings, table in module doc), docs/file-size-levels.md, ui dialog optimize_ui.rs, estimator (must stay within tolerance), tests crates/engine/tests/reduce_levels.rs.

1. First find WHY Light == Medium on real files (suspects: Medium only touches images above 200 ppi and JPEGs only if saving >=10%; real files are often already <=200 ppi or already JPEG at low quality, so nothing happens). Test with real PDFs in C:\Users\kochurin.a\Downloads (read-only, do NOT commit them, no private data in fixtures) and with synthetic fixtures at 96/150/200/300 ppi. Report sizes per level before/after.
2. Evaluate and implement what fits (pure Rust, deny.toml/AGENTS.md rules; justify any new dependency):
   - Lossless JPEG transcode for JPEG images we do not resample: optimized Huffman tables + progressive scans (jpegtran/mozjpeg-style), typically -5..-15% with zero loss. Candidate crates: jpeg-encoder (progressive, optimized huffman) or own coefficient-level recoding; keep only if pixel-identical decode.
   - Quality-targeted re-encode instead of a fixed quality: per image binary-search the JPEG quality so that a perceptual metric (SSIM/MS-SSIM or a simple butteraugli-like proxy implemented locally) stays >= a per-level threshold (e.g. Medium ~0.985, Strong ~0.97), never going below a floor quality (Strong floor ~65, not 55). Re-encode only when it is smaller than the original by a margin.
   - Chroma subsampling choice (4:2:0 for photos, 4:4:4 for images with sharp coloured edges/text/line-art); detect text/line-art/screenshots (few colours, hard edges) and keep them lossless (Flate+predictor, or palette/indexed reduction when exact) instead of JPEG.
   - Resampling: Lanczos3/area-average for downsampling, only when effective ppi is above the target by a margin (Medium target ~150 when >=220; Strong ~110 when >=150), never upsample, keep mask/SMask alignment, do not resample images with ImageMask or tiny images.
   - Stop re-encoding when the result would be larger or SSIM too low; keep the original stream.
   - Dedupe identical images/streams, drop unused resources, font subsetting if feasible (otherwise list as not done).
   - Zopfli-style deflate only if a pure-Rust crate passes deny.toml; otherwise skip.
3. Redefine the presets so they are DIFFERENT and honest: Light = lossless only (structure, dedupe, lossless JPEG transcode, flate best); Medium = quality-targeted, visually lossless; Strong = bigger reduction but with the SSIM floor, still no obvious artifacts. One table in optimizer.rs + docs/file-size-levels.md + dialog text (en+ru, ru.tsv rules as in task 024, run zz_rehash.py).
4. Tests: fixtures with photo / scan / screenshot / text-on-image; assert size ordering strong < medium < light < original on each where possible, SSIM floor respected per level (compute SSIM of rendered or decoded image vs original in the test), lossless transcode is pixel-identical, estimator within tolerance.
Constraints: never-panic rules for new non-test code, no unwrap on input-derived values, large files must not freeze the UI, Sintec branding. Done when fmt, clippy -D warnings and cargo test for touched crates are green. Report: why Light==Medium, techniques added, measured size and SSIM per fixture and per level, limitations.

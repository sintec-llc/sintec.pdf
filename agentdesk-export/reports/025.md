## Worker summary

All 5 failing tests now pass. All three were real code bugs; I didn't change any test assertions.

**1. Audit: the three `faux_redaction_*_after_a_long_label` tests.** Our commit 7f20422e ("table cells written as one TJ per row are separate text") made `text_lines` split a TJ at gaps of 3 em or more. That split one line into "Social insurance number:" and "123 456 789". So the audit reported only the value, and a cover over part of the value was no longer found at all, which is a security regression. Editing still needs the split lines, because `replace_line` and the paragraph line lists use their numbering. So:
- `crates/edit/src/text.rs`: added `pub fn drawn_lines`, which returns the lines as the content streams draw them (upstream's behaviour). `text_lines` is unchanged.
- `crates/audit/src/lib.rs`: one call changed from `text_lines` to `drawn_lines`, with a comment. **This does change the audit crate's code, not just a dependency.** I couldn't find a fix inside `edit` alone that keeps both behaviours. The audit tests are untouched.
- `crates/edit/src/tests.rs`: the table test now also checks that `drawn_lines` keeps each row as one line. With the fix reverted, the 3 audit tests fail.

**2. Content: `text_tool_single_click_retypes_added_text_without_another_item`.** This only fails when the app is built with the craft-fonts repo (`CRAFT_FONTS_DIR` set), which enables the Arabic case; without them it always passed. Our Font substitution window opened over the page because the added Arabic text uses the app's own bundled Noto Sans Arabic, so the click landed on the window. In `font_substitute.rs`, `suggest_fonts` no longer suggests replacing a font that the app ships itself. It failed before the fix and passes after, built with the bundled fonts.

**3. ui_group: `preferences_theme_cards_and_use_system_setting_stay_in_sync`.** After the UI port, Preferences had two nested scroll areas: upstream's in `dialogs.rs` and ours inside `preferences_body`. The outer one took the clicks meant for the theme cards. I removed upstream's outer one and kept ours, which keeps the title and OK visible.

fmt and clippy `-D warnings` are clean on edit, audit and ui-egui. The audit and edit tests pass, and so do the ui-egui `content`, `ui_group`, `font_substitute`, `editing` and `text_box_frames` targets. I also left a separate build folder from the bundled-fonts runs, `C:/Users/kochurin.a/sintec-pdf/target-025-fonts`, which can be deleted.

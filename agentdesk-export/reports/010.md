# 010: Tab drag into another window's tab strip must work across processes

## Brief

Goal (task 010): dropping a tab from window A (process P1) onto the tab strip of window B (process P2, or the same process) must add the document to B at the pointer's gap and remove it from A. Works both directions, including unsaved work. The source closes the tab only after the target confirms it took it. On failure the tab stays and a notice shows. The single-process behaviour must not change.

## Worker summary

You can now drag a tab onto the tab strip of a Sintec.PDF window in another process, in either direction, and it lands at the gap under the pointer. That includes unsaved work. I couldn't test it with two real processes here, so the cross-process drag has only been checked in the test harness. `reports/010.md` has a 10-step checklist for trying it by hand with two windows.

`cargo fmt --all --check`, `cargo clippy -p pdfcraft-ui-egui -p pdfcraft --all-targets -- -D warnings` and `cargo test -p pdfcraft-ui-egui -p pdfcraft` all pass. The web (wasm) build was not compiled because that target isn't installed here; the new network code is switched off for it.

**How it works** (new file `crates/ui-egui/src/tab_transfer.rs`):
- **Where windows are:** each process writes a small `<pid>.json` into a `Windows` folder beside the crash-recovery folder (`%LOCALAPPDATA%\Sintec.PDF\Windows` on Windows). It holds a local port, a random token and the screen position of each window's tab strip and tabs. The file is rewritten every 2 s and removed on exit. Files not rewritten for 10 s count as dead and are ignored, and at most 32 are read.
- **The hand-off:** on drop, the source sends one message to the target over localhost: a saved file goes by its path, unsaved work by a recovery entry, as with tear-off. The target checks every field and size, opens the document at the gap and page, and confirms.
- **Closing the source tab:** this happens only after the target confirms. If the target refuses, is busy with a dialog, doesn't answer or has died, the tab stays, the unused recovery copy is deleted, and a notice says why.
- **Waits are short:** 0.5 s to connect and 8 s at most for the answer, so a dead window fails almost at once. If the source gives up while the target is still opening, the document ends up open in both windows rather than lost.
- **Same-process behaviour is unchanged.** Moving within the window's own strip or to another window of the same process still wins over a cross-process drop. A cross-process drop only counts when the pointer is outside the source window.

**Other changes:**
- `chrome.rs` publishes the strip positions, and the drag now also shows "Release to move it to that window" over another process's strip.
- `tear_off.rs` has the sending side, built on the existing tear-off code.
- `apps/pdfcraft/src/main.rs` starts the listener when the app starts.
- 7 new Russian strings were added to `ru.tsv` and the hash rehashed; the entry in `parity/acrobat-features.toml` was updated.

**Tests:** 13 unit tests cover message and registry validation (stale entries are ignored), the drop decision, and real localhost exchanges. 5 kittest tests cover a real drag onto another process's strip, a refusal, a dead target, no target, and the receiving side.

**Not done yet:**
- A strip hidden under a third window still accepts a drop, because window stacking isn't checked.
- The target window doesn't highlight its gap while you hover over it.

NOTES:
- Cross-process tab moves live in `crates/ui-egui/src/tab_transfer.rs`. The registry is in `RecoveryStore::default_dir().parent()/Windows`, and published rectangles are in physical screen pixels: (point + window origin) × pixels-per-point.
- The app holds the listener in `PdfCraftApp.tab_peer` (not on wasm). Tests use `Peer::start_as(registry, fake_pid, wake)`; a test that drags to x=1600 in a 1400-point harness counts as "outside the window".
- `tear_off.rs::hand_off_what` (file or recovery entry, plus page) is shared by tear-off and `send_tab`. `control::random_token` is now `pub(crate)`.
